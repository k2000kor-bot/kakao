# 칼럼·해설문 품질: 샘플 vs 일반 결과 비교 및 극복

이 문서는 **샘플 칼럼 결과물**과 **일반적으로 생성되는 결과물**을 비교하고, 부족한 부분을 극복하기 위해 적용한 기준과 동작을 정리합니다.

---

## 1. 비교 요약

| 구분 | 일반 결과물에서 부족한 점 | 샘플(기준) 결과물의 강점 |
|------|---------------------------|---------------------------|
| **구조** | 섹션이 없이 한 덩어리로 나열 | 도입 → 첫째/둘째/셋째 → 결론, 마크다운 제목·구분선 사용 |
| **도입** | 단순 요약만 있거나 반전 없음 | 핵심 숫자 요약 후 "그런데 시장은 박수를 치지 않는다" 식의 반전 한 줄 |
| **본문** | 사실 나열 위주, 해석·비판 약함 | 각 블록: 소제목 → 사실/근거 → 해석·비판, "외화내빈" 같은 함의 표현 |
| **결론** | 없거나 "참고하시면 좋겠습니다" 수준 | 인용·메타포("진통제")로 기억에 남는 한 줄 + "남은 과제" |
| **표현** | "~할 수 있습니다", "도움이 될 것입니다" 반복 | 흔한 수식어 최소화, 구체적 근거와 단정적이되 완결된 문장 |

---

## 2. 코드에서의 반영

- **비교·기준 정의**: `src/constants/sampleColumnResult.ts`
  - `SAMPLE_VS_TYPICAL_GAPS`: 일반적 부족함 vs 샘플 강점 목록
  - `COLUMN_QUALITY_INSTRUCTION`: 칼럼/해설문 요청 시 API context에 넣는 품질 지침 문자열
- **의도 감지**: `src/utils/chatInputUtils.ts` — `detectColumnStyleIntent(input)`
  - "칼럼으로 써줘", "유시민 스타일", "분석 칼럼", "해설/논설/시론으로 작성" 등 패턴 감지
- **품질 지침 주입**: `src/components/ChatGPTInterface.tsx`
  - `detectColumnStyleIntent(trimmedInput)` 이 true이면 `answer_quality_instruction`에 기본 지침 + `COLUMN_QUALITY_INSTRUCTION` 결합하여 전달
  - `column_style_requested: true` 로 백엔드에 칼럼 스타일 요청 여부 전달

---

## 3. 사용자 동작

- **샘플 결과 확인**: 웰컴 화면에서 **「칼럼 샘플 결과 보기」** 클릭 → 동일 주제의 샘플 칼럼이 대화 메시지로 표시됨. 여기서 구조·길이·톤을 참고할 수 있음.
- **실제 생성 시**: 같은(또는 비슷한) 질문을 입력하면, "칼럼으로 써줘", "유시민 스타일" 등이 포함된 문장일 경우 위 품질 지침이 자동으로 적용되어, 샘플에 가까운 구조·표현을 유도함.

---

## 4. 백엔드 활용 (선택)

- `context.column_style_requested === true` 이거나 `context.answer_quality_instruction`에 칼럼 지침이 포함된 경우, 시스템 프롬프트나 후처리에서 해당 지침을 우선 적용하면 샘플 수준에 더 가깝게 맞출 수 있습니다.
- 칼럼 전용 모드나 프리셋을 두고, 이 context를 그대로 참고해도 됩니다.

---
